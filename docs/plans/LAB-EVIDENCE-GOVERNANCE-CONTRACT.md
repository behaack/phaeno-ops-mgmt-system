# Laboratory evidence governance

Status: implemented locally; verification is recorded in [the governance checkpoint](../testing/runs/2026-09-18-evidence-governance.md). The owner approved each product decision separately in the September 18 conversation. This extends the [sample traceability plan](SAMPLE-TRACEABILITY-AND-INVESTIGATION-PLAN.md).

## Approved product decisions

1. Retain internal sample history, traceability records, investigation manifests and supporting reports indefinitely for now, independently of customer download expiry. No duration/start event or automatic evidence deletion applies. This does not transfer ownership of externally referenced raw/scientific files to POMS.
2. Before new result releases, require an exact source tube/sample mapping, sequencing run and QC evidence, analysis software/settings/reference versions, run times, input checksums and output attribution. Explained Not applicable cases are allowed where meaningful; the result-to-tube chain cannot be waived.
3. Recording another person's work or changing a recorded performer/time requires a reason and independent approval by a different supervisor. Original evidence remains visible. Proposed attribution remains unverified until approved.

## Immediate enforcement decision — September 19, 2026

The owner approved enforcement starting now and confirmed all existing records are test data. No historical backfill, inferred evidence, data deletion or grandfathered approval/release is required. Both traceability and scientific-evidence checks default on. All subsequent result registrations, scan finalization, scientific approvals and releases (commercial, Trial and automatic payment-hold release) must meet the current requirements, even when a saved test package predates enforcement. Older incomplete records stay readable and unchanged; use newly captured evidence and explicit replacement/reanalysis records before continuing. Deploying the changed application remains a separate action; this decision does not claim the running production deployment has changed.

## Implemented boundaries

`PSeqOrderToCash:RequireScientificEvidence` and `RequireResultTraceability` now default true and are enabled in the application configuration. When enabled, both staff and pipeline analysis registration pin profile 1; all new manual/pipeline result registration must reference a profiled analysis. An explicitly supplied `requirementsVersion: 1` also pins the profile. Profiled analyses keep their requirements even after the deployment switch is disabled. Existing unpinned runs remain unchanged and cannot satisfy a subsequent approval/release under the current policy. All approval/release boundaries recheck the active policy, even for packages whose saved requirement flag was false.

Profile 1 requires analysis software versions, a settings checksum, reference versions, explicit start/completion times and one exact input role for every sequencing output. Each sequencing output needs start/completion times plus a QC summary and named metrics or a checksummed QC document. Explained `notApplicable` keys are limited to `qc`, `software`, `parameters` and `referenceData`; contradictory recorded/N/A values are rejected. Source/sample/run identity, times, checksums and output attribution cannot be waived. Producing performed steps also need performer/time evidence; pending reviews and rejected on-behalf entries without a later approved amendment block the governed release path. Coverage does not certify scientific validity or external file availability.

Staff may record another identified Phaeno person's work, including historical inactive staff. The recorder remains authenticated and separately identified. On-behalf entries create proposals atomically with exact covered step records. Supervisors can propose amendments and approve/reject another person's proposals through Sample history. Review decisions are immutable, reasoned, scoped to the job/sample and protected from stale-base approval. A rejected amendment leaves valid original evidence intact; a rejected on-behalf entry remains unverified until a corrected proposal is approved. Personal late entries still require a reason; multiple performers and per-tube time overrides are outside this slice.

Migration `20260919050429_AddLabEvidenceGovernance` adds two restrictive, append-only review tables and the nullable analysis requirement snapshot. It was applied to verified local development and isolated reference databases only. Internal history deletion and private preparation/QC attachment deletion are guarded separately from customer deliverable expiry. External raw/reference files remain the producing team's responsibility. Hosted backup and actual producer/bench acceptance remain outstanding.
