# Libraries, batches, and sequencing

Library and batch records preserve the physical lineage from submitted specimen through prepared library and outsourced sequencing custody.

## Choose original S3 files when configured

Computer uploads show a progress bar, transferred bytes and percentage for the current file or ZIP. **Checking selected file**, **Uploading**, and **Finalizing storage, verifying and scanning** are separate phases. A completed transfer does not by itself mean that scientific input has been admitted. Verification may show an indeterminate bar until its result is known.

For a bundle, create a ZIP on your computer and choose the batch ZIP workflow. POMS completes storage of the ZIP before scanning and inspecting it. Review its exact library/run/read/group/part mappings, then choose **Import reviewed FASTQ files**. Extraction shows how many selected files have been verified. Each admitted FASTQ is stored separately under its scientific capture; the original ZIP remains temporary transport. S3 stores the objects while POMS performs inspection and extraction. Current displayed file, archive and scanner limits still apply.

The file selector uses **Upload from computer** when local upload is the only available option. When S3 is configured, use its **Actions** menu to choose **Upload from computer** or **Choose original S3 file**. In vendor-results intake, complete the library, purchased run, preparation, layout and read/group/part mapping before choosing an original FASTQ. Only originals under that sample/library/submission/run are offered. Choose R1 and R2 separately with their exact read roles, and wait for verification before saving successful results.

POMS checks the complete file, records its checksum and size, scans it, and validates FASTQ contents without creating another stored copy. Over-limit, changed, unavailable or unscannable files cannot be admitted. A saved source locator does not approve an analysis or publish a Customer result. Keep original evidence available; if its recorded version or contents are no longer retrievable, investigate the source rather than substituting a different file.

Original-file registration requires an exact S3 object version. If POMS reports that versioned source uploads are required, contact Operations before the producer uploads or replaces files. POMS does not enable bucket versioning or recover a missing original automatically.

New S3 scientific uploads are organized by Customer, Job, sample, library and sequencing event. A new preparation has its own library; sequencing an existing library again has its own event. Raw files remain separate from each assembly attempt's outputs. Reassembling the same inputs creates another attempt with its own settings, outputs, QC and outcome; it does not overwrite earlier work.

## Record sequencing and analysis evidence

Open a job, select its specimen, and go to **Sequencing & analysis**. Operators and Supervisors can choose **Record sequencing output** or **Record analysis run**. Reviewers can open the saved records without changing them. Each file or run name links to its own detail page.

For sequencing, select the recorded **Library / tube** and **Sequencing submission**. The submission must contain the exact library and barcode in its saved manifest. Upload the actual sequencing file and enter its actual run reference and sample/index/lane mapping. POMS records the file identity, checksum and size automatically. Record the actual run start and completion times, plus a QC summary and named measurements or a supporting document with role `qc`. The library must have completed the required preparation and QC before the record can be saved.

For analysis, select every exact sequencing input and describe each input's role. Inputs must come from the same source-tube attempt and purchased sequencing run. Each purchased run has its own result, even when runs reuse one prepared library. Record the actual analysis run, start/completion times, software and reference versions, and settings checksum. Every new staff-recorded analysis pins the scientific evidence requirements in effect for this screen. Where inapplicable, QC, software, settings or reference evidence may use **Not applicable** with an explanation; source identity, times and file attribution cannot be waived.

Times use your browser's local timezone, displayed above the fields. If a clock change repeats a time, choose its occurrence. **Additional run details** includes instrument, flowcell, lane, pool, index mapping, workflow version and optional submission/receipt times. Supporting documents require an exact external version, checksum and byte size. These references do not upload the underlying files or confirm their availability.

Use **Record correction** from a sequencing record or **Record reanalysis** from an analysis record to create a linked replacement with a reason. Review the prefilled facts against the actual work before saving. Earlier records remain unchanged and can be opened through **View preceding record**. Failed saves retain your entries; retrying unchanged evidence does not create a duplicate record.

Where the legacy manual-upload workflow is still enabled, authorized platform administrators can choose **Upload result** from an analysis record. The selected analysis is carried into the upload. Identify the exact row, entry or range for this sample, or confirm that the entire file belongs to it. Upload does not approve or release the result. This action is unavailable when governed result delivery has retired manual uploads.

## Track sequencing assembly

Open **Lab operations > Data assembly** for PSeq Service work. **Sequencing inputs** lists verified FASTQ input sets by specimen and run; start assembly from the relevant input set. **Sequencing assembly** tracks requested attempts, progress and outcomes. Select a specimen/run there to open its attempt. Partner Assembly cases are a separate concern, available from **Order ops > PARTNER SERVICES > Data assembly**; open the case and select **Open Lab work** for its manufacturing workflow.

The processing connection is not yet configured. POMS displays **Assembly setup required**, and **Start assembly** remains unavailable until the external service is connected. This notice does not mean a job failed.

For a connected service, Start assembly selects the registered inputs for one sample/run and a configured processing recipe. The server verifies the inputs before accepting the request. Processing continues after the browser closes. Percentage progress is live display information; individual updates are not retained. After a connection interruption, the percentage may be unavailable until a fresh update arrives.

Start assembly saves the attempt before dispatch and waits for DPS to accept
the command. Broker delivery alone does not establish acceptance or execution.
If dispatch fails, is rejected or has no confirmed response, POMS displays an
error. When an attempt was already saved, choose **Open saved attempt** to inspect
its delivery and recovery state; closing the dialog does not cancel it. The
original input and recipe selection stays fixed while that saved attempt needs
reconciliation. Do not create another attempt to work around an uncertain response.

For connected DPS work, cancellation also reports a dispatch error when DPS does
not accept the command. An accepted cancellation request is still separate from
confirmed termination. Recovery queries the same attempt and preserves any
actual completion that wins the cancellation race.

Active assembly jobs show a progress bar in the assembly list and attempt detail. A fresh percentage reported by the service fills the bar; when no current percentage is available, an indeterminate bar says **Progress unavailable**. The job's status still applies. A reported 100% does not replace a confirmed final outcome or satisfy scientific QC/release. Finished jobs show their recorded outcome instead of retaining a live percentage bar.

Each attempt retains actual start and stop times and its final disposition: succeeded, failed or terminated. These times are displayed in the browser's local time zone. Elapsed duration is calculated from the recorded start and stop. A request cancelled before execution has no fabricated execution times. **Job history** contains meaningful lifecycle events, not a percentage-update feed.

Repeating an ended attempt requires a reason and keeps it linked to the earlier attempt for the same purchased run. **Request cancellation** is available only when the job can still be stopped; a request does not confirm termination. The external service may complete the job before cancellation takes effect.

Successful execution does not approve or publish results. Record the completed analysis and scientific evidence through the existing capture workflow. When the matching analysis is available, **Link completed analysis** checks its provider execution, inputs and actual start/stop times. Result files still require verification and scientific QC before the separate customer-release workflow.

For DPS-produced outputs, POMS verifies the exact output manifest, file versions,
checksums, sizes and scans before admitting the files and linking their producing
analysis. An admission problem remains visible and is retried separately from
the saved execution outcome. Missing scientific evidence, QC, independent approval
and Customer publication remain separate requirements.

The attempt's **Delivery and recovery** section shows saved Run/Cancel delivery attempts and their confirmation status. Command delivery does not prove processing started. An unconfirmed receipt, start or cancellation remains visible as attention required; recovery retries with bounded delays and escalates after the configured interval (30 minutes by default). A successful result can arrive after a cancellation request and remains the recorded outcome. Conflicting evidence preserves saved execution facts and requires Operations reconciliation.

Authorized Phaeno users receive refresh notifications for the assembly attempts they are viewing. The page reloads saved status from the API after a notification or reconnect and continues polling when notifications are unavailable. Closing the page does not cancel server recovery. Live DPS transport and independent Operations alerts still require integration setup.

## Prepare a library

For tray-based preparation, open **Library prep** and the preparation batch. Lists and headings show the readable service and preparation identity; the saved immutable identifier and physical tray barcode remain separate on the record. Select an eligible source tube from its job, then scan its physical barcode into an empty tray position. From a tube's actions, assign its distinct library tray tube using an existing manufacturer barcode or a POMS-generated label. For a manufacturer-barcoded tube, select its manufacturer and scan the printed barcode. The accessioned source tube, library tube and reusable tray each retain their own identity. A new POMS tube is **Label pending** until you print its DataMatrix label, attach it to the physical tube and scan the printed label back. Complete that verification before recording the transfer.

When the approved step includes **Biological material**, scan both the accessioned source and destination library tube and enter the actual decimal amount pipetted in the configured unit. The two physical tubes must have different printed barcode values so the scans identify the intended source and destination. POMS subtracts that amount from the source and records it in the destination. The form accepts up to 28 fractional places and checks that the resulting source and library-tube balances can be recorded exactly. Select **Material exhausted** only when no usable source material remains; it preserves the actual transferred amount and separately records any adjustment to the source balance. Exhausting the source does not prevent continuing preparation with the transferred material.

Choose **Create library output** to record the prepared quantity, unit and storage location, then **Confirm output identity** by scanning its barcode. For a manufacturer or registered supplied tube, scan its existing supplied label; printing is unnecessary. For a POMS-generated tube, print, attach and verify the label first. When a library tray tube has been assigned and its transfer recorded, output uses that same tube. Prepared yield is a separate measurement and does not consume the source again. Earlier approved workflows without a Biological material field retain their existing output workflow; adopt a newly approved configuration to capture input transfers.

The job, specimen, source and preparation attempt are carried forward. Completing the final preparation stage creates the library and reuses its recorded QC evidence; do not enter the same measurements or disposition again. Complete the preparation batch before adding its eligible libraries to a sequencing batch. Open a source or destination tube to inspect its remaining amount and transfer history; an unrecorded historical balance remains unknown.

For historical individual work outside preparation batches, the existing library form still links source and library containers to the specimen and completed preparation execution, followed by its separate library QC entry. A manufacturer-barcoded library has a distinct internal library key; its physical tube keeps the manufacturer's printed barcode for scans and custody. Existing POMS-barcoded libraries retain their barcode-based keys.

Only a library with passed QC can enter a sequencing batch. If QC fails, preserve the failed library and use the documented rework or replacement path.

## Build a batch

A **preparation batch** tracks the selected source tubes and the library tubes occupying its tray positions through library preparation. A **sequencing batch** groups completed, eligible libraries for sequencing. These are separate records. The preparation workspace shows each library's current sequencing membership and offers **Add to sequencing batch** for eligible, unassigned libraries after the preparation batch is complete. The assignment form offers **Create sequencing batch** when a new draft is needed. Creating the batch and saving its library membership are separate actions. Draft choices show the descriptive name and immutable number. Duplicate membership within a batch is rejected. A library may supply another sequencing batch when its previous batches and sendouts are complete and purchased runs remain outstanding.

A batch may contain libraries from different organizations and Commercial orders. Give it a human-friendly name and optional notes. POMS assigns the current **External sequencing** type and a date-stamped, scanner-safe batch number when the batch is created. The name helps operators recognize the run; the batch number remains the immutable identifier. Add only the required library identifiers and operational facts. Do not copy Customer names, prices, order notes, or other confidential Commercial details into the batch manifest.

The batch number is the title in **Sequencing batches** and its dedicated workspace. A descriptive name appears below when it differs from that number. Select the batch number to open its workspace. It shows the next step, members and tube pairs, saved transfers, provider, frozen manifest, and custody/status history. Record actions are available from the list and workspace. When results still need recording, the workspace provides a **Record results** button beside the Next step description; otherwise, choose **Actions → Edit results** to update the recorded result and its verified FASTQ file sets.

For scan-first entry, open **Sequencing batches**, expand **Scan libraries** in the list header, select a draft batch, and scan each physical library container. If two manufacturers use the same printed value, choose the physical tube's manufacturer in the optional field before scanning. The scan section starts collapsed and retains your entries when collapsed again. POMS accepts a container linked to a library with passed QC. A previously sequenced library can be reused while purchased runs remain, provided its material is available and its earlier batches and sendouts are complete. An unknown or ambiguous barcode, non-library container, failed QC, active earlier assignment, or duplicate membership is rejected without changing the batch. Open the library record to review its sequencing history. A successful scan clears and refocuses the field for the next container.

Confirm membership before starting the batch. Once started, preserve the membership history and use supported add, remove, or exception actions rather than rewriting the original manifest. Scanning proves the container identity used for entry; it does not replace the approved physical manifest and custody checks.

When an authorized operator chooses **Begin shipment preparation**, POMS opens a confirmation modal with the actual preparation time prefilled. Correct the time when preparation began before it was entered; POMS stores the submitted value as UTC and retains the server audit timestamp. Final batch completion follows the vendor results workflow below. Use the **Status** filter above the batch list to focus on drafts, shipment stages or Results received without changing which draft batches are available for scanning.

## Create an outsourced sendout

If allocation or transfer confirmation is interrupted, use the offered retry before recording another action. Reopening this batch with the same account and browser restores the original command, even after a reload or browser restart. Retrying confirms the earlier result without allocating a second tube or deducting material twice. Do not repeat the physical pipetting because confirmation was interrupted.

From a batch's **Actions**, open **Prepare sequencing tubes**. Assign a separate tube for each library using a manufacturer barcode or a POMS-generated label. Select the physical tube's manufacturer when using its printed barcode. A POMS-generated sequencing tube remains **Label pending** until its printed DataMatrix is scanned back; use **Print label** before recording the transfer. The sequencing tube's printed value must differ from its source library tube's value. Record the physical transfer by scanning the source library and destination sequencing tube, entering the actual decimal amount and matching unit, and recording when you performed it. The form accepts up to 28 fractional places and checks that the remaining source balance can be recorded exactly. The optional **Material exhausted** override applies to the source library. The transferred aliquot belongs to the sequencing tube; the remaining library stays in its original tube.

After shipment preparation freezes the records, the action becomes **View libraries**
with an eye icon. Review library identities, source and sequencing tube barcodes,
transferred volumes and saved transfer evidence. Users without preparation
permission also receive this read-only view.

## Ship and track vendor sequencing batches

Open **Lab operations > Sequencing batches**. Select the batch number to open its
workspace. The list filters by shipment stage or final outcome and displays the
vendor, tracking reference and expected completion. An elapsed ETA is marked
**Overdue** until results are received.

The workflow is **Prepare shipment → Shipped → Vendor received (ETA) → Results received**. Use the batch's **Actions** for each
stage. Operators and Supervisors can record shipment, vendor progress, results
and verified FASTQ files; reviewers can read the records.

The tracker shows four stages. Results received is the single final workflow
status; Success or Fail belongs to each submitted library. Recording results
completes the final stage and batch together. The detail header holds status,
times and one Actions menu.

After assigning passing libraries, choose **Begin shipment preparation**. Record
the actual preparation time; this does not mean the vendor has started sequencing.
Use **Prepare sequencing tubes** to confirm every physical tube and transfer against its
captured Catalog minimum. Choose **Prepare vendor shipment**, select the vendor,
its **Sequencing service** product and one of its named shipment addresses. Review
the complete address shown below the selections. Changing vendor clears the
service and address choices. A Purchasing administrator maintains these records
under **More → Purchasing → Suppliers**; an active service and address are required.
The preparation dialog shows the tube-pair readiness count and an expandable
**Review tube manifest** list. Every pair needs a confirmed available sequencing
tube, recorded transfer and captured minimum volume before preparation can be saved.
Optionally enter carrier, tracking, vendor reference, ETA and notes. **Prepare shipment** retains
the reviewed vendor, service and address, and freezes the member identities, tube barcodes and aliquot
amounts. Review the actual package against this manifest. **Download tube manifest**
saves the frozen tube list and current shipment details as a CSV for handoff.

Before marking **Shipped**, record the carrier and tracking reference through
**Update shipment and ETA**. Before dispatch, this action can explicitly select a
different active address belonging to the same vendor, with an update reason.
The saved vendor and service remain fixed. Catalog edits do not replace the saved
destination. Mark Shipped after physical dispatch. The destination
cannot change afterward. Mark **Vendor received** using the confirmed receipt time
and the vendor's required completion ETA. Record actual run times when recording the returned results. Use **Update shipment and ETA** to retain tracking
or ETA changes with the required evidence/reason.

Each status confirmation names the batch, vendor and proposed stage, and shows
the saved sequencing service, destination, carrier and tracking for review. Vendor
receipt starts with the saved completion ETA; check it against the vendor's confirmation.
The optional **Vendor reference** is separate from the shipment's tracking reference.
Enter the
actual occurrence time and required provider/custody evidence. Times use your
browser's local timezone and are saved in UTC. An event cannot be in the future
or precede the preceding stage. History retains the actual time, separate entry
time and operator. Recorded custody and status history remains available in the
batch workspace; stage actions retain their own evidence.

The workspace places shipment details, final outcomes and data handoff ahead
of the longer physical transfer history. Expand **Frozen tube manifest** to review
the submitted tubes. **Next step** names the next action and its prerequisite.
When batches for one Job progress at different times, recording the later batch's
shipment does not move the whole Job backward from data processing or clear a hold.

Closing a vendor or status form with unsaved entries opens a discard confirmation.
Choose **Keep reviewing** to retain your entries, or **Discard changes** to close
the draft. Focus returns to the batch's Actions control after closing. Saving a
shipment update requires its reason and uses **Save shipment changes**.

## Record vendor results and upload FASTQ files

Choose **Record results** beside Next step after vendor receipt, or from the
list’s **Actions**. The dedicated workspace combines the vendor report with its
FASTQ uploads. Enter the vendor job reference, actual run start/completion and
results-receipt times. Receipt may be later than completion; times use your
browser’s timezone and are saved as UTC. Future or out-of-order times are rejected.

Choose **Batch outcome** Success or Fail. Success applies to every library unless
selected as a failed exception with its required reason. Fail marks all libraries
failed and hides uploads and exceptions; record the common failure reason in
Results notes. **Run not performed** shows only vendor reference and its required
reason. It has no actual run or receipt times and closes as Run not performed.

Use **Batch ZIP** to upload one archive containing the batch’s FASTQ files, or
**Individual files** to capture each library separately. For a ZIP, POMS inspects
paths, declared sizes and supported files, then scans the complete archive.
Review the proposed library matches, explicit run/preparation/layout choices,
R1/R2 roles, groups, parts and actual group descriptions. A filename or folder
match is a proposal; confirm it against the vendor evidence. Unmatched names
need an explicit library selection. Explain every excluded FASTQ file.

Confirm the ZIP mapping review, then choose **Import reviewed FASTQ files**.
Imported files undergo the same individual FASTQ structure, read-identity,
checksum and scanning checks. Completed imports are retained when another entry
fails; review its mapping and retry. Ordinary accompanying reports/manifests
appear as **Other ZIP files · not imported**. Upload scientific QC reports in
Record QC with the correct sample/package scope.

ZIP size, expanded bytes and entry counts are tentative configurable limits;
the effective transfer limit also respects the scanner. ZIP staging expires at
the draft’s deadline; imported admitted FASTQ files remain preserved. Encrypted
ZIPs, symbolic links, unsafe/duplicate paths and nested archives are unsupported.

For every successful library, select its actual purchased run, whether the library
was newly prepared for that run or reused, and the actual paired-end or single-end
layout. Enter the flowcell/lane or describe a merged read group using vendor
information. Group and part numbers identify explicitly grouped or split files;
they begin at 1 and must be consecutive. A paired group/part needs both R1 and R2.

Select a FASTQ file, or an R1/R2 pair with recognizable vendor names. A single
paired-end file requires its explicit read role. Review each uploaded file’s
library, run, group, read and part. POMS retains the original vendor filename and
assigns an immutable library-result file-set name. It calculates checksums and
size, checks FASTQ structure and compression, scans the complete file and verifies
stored bytes. Paired files must have matching counts and ordered read identifiers.
This verification does not itself establish scientific validity or biological
sample identity.

The displayed file/layout limits are tentative configuration values. The effective
file limit also respects the available scanner. Contact Operations if a vendor file
exceeds it; a manually entered location does not satisfy upload coverage. Failed
libraries do not require a file set. **Start a new file set** retains the previous
set and lets you explicitly capture a replacement mapping or changed files.

**Save draft** preserves incomplete form entries without recording receipt or
creating a results version. Verified files are retained. Reopen the workspace to
resume its saved draft and select an existing draft file set. Select the same
unchanged file and mapping to resume confirmed portions within the displayed
staging lifetime. Expired untrusted portions are cleaned up; admitted files remain
internal evidence. A failed transfer or verification retains retry guidance.

If the submission changed or the draft expired, choose **Restart draft** and
review the confirmation. POMS preserves your current entries and carries complete
verified file sets into a new draft for explicit review. Confirm the mappings again.
Incomplete sets stay preserved but require a new file set. Restart does not change
a saved result. Reselecting an inspected ZIP retains its reviewed mappings and
completed import identities so partial imports can resume.

Before final save, confirm all required vendor files are present and correctly
mapped. **Record results** saves vendor metadata, library decisions and the exact
verified file sets together. Incomplete or unmapped successful-library files block
save. Assembly cannot start from partial sets or missing read mates/parts.

**Actions → Edit results** opens the same workspace. Every edit needs a fresh
Results notes explanation. Retain unchanged verified file sets or upload an
explicit new set. A newly successful library must receive complete files. Initial
capture saves v1; each correction saves the next number with author, time and note.
Library exceptions belong to that exact result version. Editing an exception's
reason or outcome preserves the prior recorded fact; the current batch shows the
latest version's exceptions only.
Notes-only edits and unchanged libraries retain their exact input identities and
existing analysis links. Changing run details, files or a library outcome can
invalidate affected assemblies. A queued assembly rechecks the current results
before dispatch. Changes to inputs already being dispatched or processed require
cancellation/reconciliation or final disposition first. If affected packages are
approved or published, the Result Release Manager must withdraw those packages
before the vendor correction can save. The workspace shows the affected approved
packages. Their history and internal files remain preserved.
**Results versions** opens exact read-only outcomes and file metadata. Earlier
location-only snapshots stay readable; their strings are not imported or treated
as verified bytes. Current batch returns to the latest record.

The current batch's **Verified FASTQ file sets** panel shows each library's
purchased run, file-set version, verified file count and read layout. Open its
results-version link to inspect the exact filenames, read/group/part mappings
and checksums. Uploaded file sets satisfy the data handoff; an additional
external storage reference is not required. External references remain optional
and unverified. If saved file sets cannot be loaded, use **Reload file sets**;
the batch does not infer that the files are missing.

A saved result correction never rewrites inputs already used in an assembly.
Superseded inputs need a new assembly/reanalysis and fresh review before further
publication. A run with registered scientific outputs cannot become Run not
performed. Library outcomes do not automatically fail the specimen, consume more
material, purchase replacement runs or approve/release Customer findings.

## Assembly QC and Customer handoff

Open **Lab operations → Data assembly → Sequencing inputs** to review available
specimen/run input sets. Use **Sequencing assembly** to track requested attempts. Select the complete registered files
and an explicit processing recipe/version before Start assembly. The actual
processing connection remains required; setup guidance is shown while unavailable.

After a successful reconciled attempt has its completed analysis and verified
output package, choose **Review QC** from the attempt’s Actions. The QC workspace
shows exact packages, files and retained decisions. **Record QC** opens a dedicated
capture page. Select the exact package, Pass / Fail / Hold, a required decision
note and uploaded QC report. Named measurements are optional. Before Pass, confirm
that the report covers the assembly output and all listed sequencing inputs.
Automatic scientific threshold checks are not configured.

Each saved QC decision is a new retained version. Fail/Hold blocks scientific
approval and Customer publication. Pass permits independent scientific review;
it does not publish files. The reviewer follows the existing source/evidence and
actor-separation rules. From an approved package, open the existing Result release
workspace; the Result Release Manager chooses **Actions → Release to Customer**.
The Customer then downloads that exact version from the owning Job’s Files and
results under its retention rules. Internal evidence remains preserved.

## Respect the implementation boundary

POMS owns verified uploaded FASTQ custody, result/file-set bindings, processing
attempts and QC evidence. A real DPS connection with exact local-input access and
verified output registration is still needed for automatic assembly execution.
POMS does not simulate scientific processing or manufacture provider completion.
Scientific approval and explicit Customer publication remain separate.

Until the processing service is connected, the assembly workspace reports that
assembly is unavailable and cannot start an actual job. Complete verified uploads
and vendor results can still be saved. A successful application test is separate
from an actual assembly, scientific approval or Customer publication.

## Record library quality evidence

For library QC, select Pass or Fail and record the observations and decision basis. Add named measurements with their values and units as needed. POMS retains those structured observations with the library; operators do not need to prepare JSON. The applicable method still determines the scientific acceptance criteria.


## Sequence a sample more than once

A purchased sample-sequencing run is one sequencing of one sample. Twenty samples sequenced once and one sample sequenced twenty times both use 20 purchased runs. Tube count and library-preparation count are separate.

One prepared library can supply multiple sequencing runs. To use it again, retain the original preparation and QC evidence and select that library when recording sequencing output. If another batch is needed, complete the previous batch and sendout, then use **Add to batch** in the job's library list or scan the library into a draft sequencing batch. POMS checks for outstanding authorized runs and rejects simultaneous batch assignments.

For a fresh preparation, open the specimen and select **Prepare a new library**. Select and scan an eligible source tube. If using a previously successful source tube, confirm material remains and record the supporting evidence. Complete the new preparation, output identity and QC through the existing workflow.

In the vendor results upload workspace, select the actual purchased run number, preparation choice and library file set. POMS registers admitted sequencing inputs with their exact saved submission and run linkage. Use the sample’s Scientific evidence for additional scientific evidence or explicitly linked corrections. The same machine run can contain several purchased runs of a sample; record their distinct sample mappings and purchased run numbers.

Additional files use the same purchased run number. A linked correction or a replacement after failed sequencing retains that number and records its reason. Corrections and reanalysis do not purchase or complete another unit. Each output retains its producing library and preparation attempt. A successful preparation alone does not complete a purchased run: approved results must cover every allocated run, and delivery remains incomplete until the results for all runs are published.

## Resuming scientific file uploads

The file picker shows the current limit (normally 100 MiB). A 50 MB file is within this limit. POMS transfers the file in portions and verifies its full size, fingerprint and malware-scan result before it can be used as evidence. This does not establish the scientific validity of its contents.

If the connection fails, choose **Resume upload**. In the same browser tab, selecting the same file after returning to the page also resumes confirmed portions for up to 24 hours. Keep the original file unchanged. After expiry, select it again to start a new transfer. A failed replacement preserves the previously selected evidence file. If complete-file scanning is unavailable, retry verification after the service recovers.

Abandoned transfer portions expire; admitted scientific files and their receipts remain protected internal evidence. Customer result retention does not delete these internal files. Names, sample and run attribution stay the same when the configured private storage provider changes.


For specimen-level preparation and QC review, open a specimen’s **Libraries** tab. Review each library’s identity, physical library/source tubes, preparation attempt and execution, status and recorded QC. **Manage Job libraries** opens the existing Job actions; **Sequencing & analysis** shows downstream batch assignments and scientific outputs.
