# Integration failures and recovery

Order Ops uses durable invitation, notification, Lab projection, and provider-neutral result-pipeline records. A failed delivery remains attached to the original workflow with its idempotency key, attempt history, last error, and provider identifier when one exists. The retained accounting-connector queue is legacy/non-PSeq context; native PSeq AR remains local to POMS.

## Triage the failure

Open **Attention** for the owned cross-workflow exception or **Legacy integrations** for a retained connector/notification event. Identify the affected record, current delivery state, owner, age, attempts, next action, and tenant-visible consequence. Determine whether the local operation committed successfully before taking recovery action.

Common states include:

- **Invitation queued/failed/bounced/needs attention** while access remains separately pending, accepted, expired, or revoked;
- **Projection or scan failed** while the immutable result package remains unreleased;
- failed notification delivery after the underlying portal action already succeeded.

## Retry safely

Refresh the workflow and retry the existing durable integration event. Reconciliation uses the stored idempotency and external references to avoid duplicates. Do not recreate the order, quote, invoice, credit, shipment, release, or notification merely because delivery failed.

If an invitation hard-bounced, revoke and reissue to a corrected address rather than retrying it. If a pipeline submission or signed Mailgun webhook is replayed, use the stored idempotency/provider event identity rather than creating another package or delivery. If a notification failed, retry it without repeating the underlying business transition.

## Communicate the boundary

Keep the workflow’s operational state distinct from delivery state. A failed estimate synchronization prevents quote visibility, but it does not delete the quote. A failed invoice synchronization can block release, but it does not undo scientific completion. A failed email does not reverse the order action recorded in the portal.

Escalate only after the stored event, retry history, external reference, and current QuickBooks state have been reviewed. Include safe identifiers; never include credentials, payment data, or customer-confidential scientific detail in support notes.
