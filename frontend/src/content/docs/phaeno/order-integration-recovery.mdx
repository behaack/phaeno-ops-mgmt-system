# Accounting and notification recovery

Order Ops provides a manual journal-entry source report and durable notification delivery. QuickBooks Online integration is deferred, and historical QuickBooks messages cannot be retried.

## Triage the failure

Open the **Accounting** section. For an accounting concern, select the relevant date range and compare the stable entry ID, organization, workflow number, source document, reference, currency, gross amount, and balance with the operational record. For a notification concern, identify the original workflow, delivery state, attempt count, last error, and tenant-visible consequence.

An accounting report download is read-only: it does not post, reconcile, record payment, or release a file. Notification delivery may fail after the underlying portal action already succeeded.

## Retry safely

Refresh the workflow before investigating a missing accounting row. Do not recreate the order, quote, shipment, output approval, or result completion to force another row. Use the stable source ID when reconciling repeated report downloads.

Each outbound notification is claimed atomically with an expiring delivery lease. **Sending** means one worker owns the current attempt. If that worker stops before recording the result, the expired claim becomes eligible for automatic recovery instead of remaining stuck. Concurrent workers skip an active claim.

If a notification is **Failed**, correct the delivery configuration or address and choose **Retry**. If an interrupted **Sending** claim has expired and is still visible, choose **Recover**. The action returns only that message to the queue; it does not repeat the quote, order, shipment, release, or other underlying business transition. Refresh the queue before retrying when another worker may already have recovered the message.

## Communicate the boundary

Keep operational state, accounting-source readiness, credit, file release, and notification delivery separate. An accounting question does not undo an issued quote or scientific completion. A failed email does not reverse the order action recorded in the portal.

Escalate only after the operational record, report range, stable entry ID, and notification history have been reviewed. Include safe identifiers; never include credentials, payment data, or customer-confidential scientific detail in support notes.
