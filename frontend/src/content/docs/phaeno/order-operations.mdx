# Order operations

Order operations is the Commercial workspace for Customer laboratory orders, Partner PSeq kit fulfillment, and Partner data assembly. POMS owns operational state, assignments, tenant-safe communication, PSeq result release, and PSeq accounts receivable.

Use the far-left sidebar beneath the toolbar to move among **Order intake**, **Order staging**, **Lab**, **PSeq kits**, **Assembly**, **Attention**, **Result release**, **Finance**, and **Legacy integrations**, subject to your explicit roles. **Order staging** shows every Customer and its readiness blockers; a Commercial Operator may prepare internal PSeq work before the Customer administrator is active when the stage-eligibility minimum is met. Quote issue and Customer commitment remain blocked until full readiness.

When the Portal API and frontend are both running in their local development environments, **Simulate HubSpot handoff** can create a durable pending request for either a sales-assisted order or a no-charge Trial Project. The simulator requires a unique HubSpot Deal identifier and clearly identifies the resulting request as simulated. It does not contact HubSpot, bypass review, create an executable sales-assisted order, or implement the Trial Project lifecycle. Review the resulting request in **Accounts**.

The sidebar header identifies Order operations and, on wider screens, provides the pin or unpin icon. Pointer users can preview an unpinned sidebar by approaching the left edge; keyboard and touch users open it from the edge tab. Choosing a section closes an unpinned sidebar.

## Enter and find orders

- **Lab** covers Customer submission review, quote authorization, cancellation decisions, Commercial milestones, and result release.
- **PSeq kits** covers Partner order review, substitutions, backorders, shipments, and fulfillment.
- **Assembly** covers Partner intake validation, quoting, processing, quality review, and output release.
- **Attention** owns invitation, readiness, staged-order, projection/scan, unreleased-result, overdue-invoice, unapplied-cash, and reconciliation-difference exceptions.
- **Result release** publishes a scientifically approved, complete PSeq package per sample without a payment gate.
- **Finance** owns PSeq invoices, receipts/import, explicit allocation, aging, and reconciliation.
- **Legacy integrations** covers retained accounting-connector and notification recovery outside the active native PSeq AR workflow.

Use status, hold, overdue, organization, assignment, and due-date filters to narrow the queue. Assign an owner and due date when the workflow supports them. A queue assignment coordinates work; it does not grant authorization or change the workflow state.

## Keep state boundaries visible

Operational status, quote status, accounting-source readiness, payment, scientific readiness, file scanning, and publication are separate facts. Do not mark one complete merely because another succeeded. Tenant users receive a curated timeline, so record a tenant-safe reason separately from internal notes whenever an action can be seen outside Phaeno.

Order Ops ends at the Commercial boundary. Use **Lab Ops** for return-kit preparation, shipment-packet and tube comparison, PSeq kit fulfillment, specimen receipt and accession, protocol execution, Data Assembly, materials, equipment, libraries, batches, sequencing sendouts, exceptions, and scientific approval. Lab readiness never publishes a file by itself.

## Triage safely

1. Confirm the active organization and workflow before opening a record.
2. Review operational readiness, invitation delivery, scientific package, release, invoice, receipt, allocation, reconciliation, and notification states independently.
3. Check open holds, cancellation requests, overdue actions, and failed deliveries.
4. Assign the work and due date when ownership is unclear.
5. Perform the smallest valid next action and preserve the existing record.

If a record appears stale, refresh it before retrying. Never repair a failed workflow by creating a duplicate order, quote, invoice, receipt, result package, Lab work order, shipment, or release. Assign an attention item, preserve attempts, and record its resolution.
