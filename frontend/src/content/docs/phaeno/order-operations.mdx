# Order operations

Order operations is the Commercial workspace for taking in demand, preparing quotes, recording customer approval, managing orders, and producing accounting source records. PSeq Lab Service, PSeq Kit, and Data Assembly appear as order types in one Commercial order list. QuickBooks Online integration is deferred.

Use the far-left sidebar beneath the toolbar to move among **Order intake**, **Orders**, and **Accounting**. **Order intake** is where Commercial staff enter a new Customer order and review first-party sales handoffs. A custom-work handoff and a requested Trial Project still require Phaeno review; they are not an executable order or Lab work merely because the handoff arrived. Create the handoff from its CRM Company or Opportunity, then review the resulting request in **Accounts**.

The sidebar header identifies Order operations and, on wider screens, provides the pin or unpin icon. Pointer users can preview an unpinned sidebar by approaching the left edge; keyboard and touch users open it from the edge tab. Choosing a section closes an unpinned sidebar.

## Enter and find orders

Choose **New Customer order** in **Order intake** when a salesperson is taking a PSeq Lab Service order for an eligible Customer. The order remains Commercial while scope, pricing, and Customer approval are being established. Approval and exact sample-roster finalization create the immutable authorization and linked Lab work; staff do not accession specimens in Order operations.

Use **Orders** to search all Commercial orders. Narrow the list by **Order type** to distinguish **PSeq Lab Service**, **PSeq Kit**, and **Data Assembly** without turning those products into separate Order Ops modules. Open the order to review its immutable Commercial facts, quote or approval state, assignment, cancellation requests, and linked Lab workflow.

**Accounting** provides the date-filtered journal-entry source report and notification delivery recovery.

Use status, hold, overdue, organization, assignment, and due-date filters to narrow the queue. Assign an owner and due date when the workflow supports them. A queue assignment coordinates work; it does not grant authorization or change the workflow state.

## Keep state boundaries visible

Operational status, quote status, accounting-source readiness, payment, scientific readiness, file scanning, and publication are separate facts. Do not mark one complete merely because another succeeded. Tenant users receive a curated timeline, so record a tenant-safe reason separately from internal notes whenever an action can be seen outside Phaeno.

Order Ops ends at the Commercial boundary. Use **Lab Ops** for return-kit preparation, shipment-packet and tube comparison, PSeq kit fulfillment, specimen receipt and accession, protocol execution, Data Assembly, materials, equipment, libraries, batches, sequencing sendouts, exceptions, and scientific approval. Lab readiness never publishes a file by itself.

## Triage safely

1. Confirm the active organization and workflow before opening a record.
2. Review the current operational, Commercial, accounting, payment, and release states independently.
3. Check open holds, cancellation requests, overdue actions, and failed deliveries.
4. Assign the work and due date when ownership is unclear.
5. Perform the smallest valid next action and preserve the existing record.

If a record appears stale, refresh it before retrying. Never repair a failed workflow by creating a duplicate order, quote, accounting source record, Lab work order, shipment, or release.
