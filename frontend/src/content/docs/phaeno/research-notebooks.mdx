# R&D notebooks

Use **R&D** in POMS to record exploratory work without configuring an approved laboratory protocol. Its sidebar contains **Projects** and **Experiments**. On narrow screens, open R&D from the user menu.

For a step-by-step walkthrough with annotated screenshots, see [How to record an R&D experiment](/docs/phaeno/how-to-record-research).

## Access and shared work

Select the Phaeno organization. An active Phaeno user needs the **R&D researcher** role or platform administrator access. A platform administrator assigns the role through **User management**, including on a new Phaeno invitation. Other Phaeno staff and external organizations cannot access the notebooks.

Every authorized researcher can read and edit the team's projects and experiments. There are no private projects or experiment-specific collaborator lists. Department selection does not restrict this shared research workspace. Use the notebook for information appropriate to that audience; do not enter credentials or confidential customer records.

## Start a project and experiment

1. Open **Projects** and choose **Create project**. Enter a project name; its description is optional.
2. Open the project's name and choose **Create experiment**. Enter an experiment title; an experiment date is optional.
3. Open the experiment's first notebook entry by its title, then choose **Edit entry** from its Actions menu. Record the entry title and date, then capture the work.

The first entry offers Purpose, Method, Observations, Results and Conclusions. These sections are optional: remove, rename or reorder them, or add text sections and tables. To add a dated entry, choose **Add entry**, review its title and date, then choose **Create entry**. Canceling this dialog creates nothing. Create entry permanently records the entry and opens its editor; canceling that editor later keeps the confirmed entry.

An entry date describes the work; recorded and last-saved times identify when the application received each save. Initial and copied entries use the experiment date when provided, otherwise today's date in your browser's local time. The Add entry dialog also defaults to your local date.

## Record notes, tables and files

Text sections preserve multiline notes and scientific characters. Give each section a label. The **Scientific section** selection identifies its meaning independently of its label and controls which text is retained when copying setup.

Tables have editable column headings and cells. Include units in headings where appropriate. Add or remove rows and columns as the experiment changes. The notebook retains entered values; it does not calculate, convert units or judge scientific validity.

Choose a file under **Attach a file**. The displayed limit applies to each upload. Wait for upload, verification and scanning, then choose **Save changes** to include the attachment in the saved entry. If a file fails, the notes remain in the form and can be saved independently. File storage or scanning may be unavailable in an environment; retry when service is restored.

Use an attachment's action to download it. Supported verified images also offer an image preview. Other files download for use in their original applications. Removing a file section from a later draft does not delete the original bytes: older saved revisions still retain that attachment. Uploaded files remain retained even if not subsequently attached to an entry.

**Save changes** records the entry and its history. Cancel or navigate away only after explicitly deciding whether to discard unsaved edits. A save or upload in progress must finish before leaving. Changes are not saved automatically.

## Review and resolve concurrent edits

Every saved entry retains its previous content, author and time. Choose **View history** on an entry, experiment or project, then select a revision. History is read-only; it is not an approved protocol revision or scientific sign-off.

If another researcher saves first, your input stays in the editor. Review the latest saved entry, then use its **Actions** menu to keep your edits against that revision or use the latest saved entry. Keeping your edits requires another explicit save and can replace the other researcher's values; reconcile the work before doing so. **Refresh latest saved entry** reloads the saved version while retaining your draft.

If the experiment is completed during editing, choose **Reopen experiment** inside the editor and confirm. Your draft stays in place. Review the latest saved entry and choose **I reviewed the latest entry; keep my edits** before saving. The same review becomes available if another researcher reopens it elsewhere.

## Complete, reopen and repeat

Choose **Actions â†’ Complete experiment** when the experiment is finished. Completion requires no approval or filled scientific sections; it makes the notebook read-only. Use **Reopen experiment** to continue recording or correct it. Both actions retain their actor and time. Completion does not establish a scientific result or release anything to a Customer.

Choose **Copy setup** to start a new Active experiment. The copy retains section labels and order, Purpose and Method text, and table headings with no rows. It clears observations, results, conclusions, custom text, files and the previous entry history. Review the copied method before beginning the next experiment.

## Find earlier work

Projects supports name and description search. Experiments supports title, saved notebook text and table-content search, with project and status filters. Results are paged, with complete matching counts. Each experiment lists 25 entry summaries per page. Open an entry's title to read its notebook, files and history. Returning to the experiment retains the entry page. Search does not inspect attachment contents. Returning from an experiment preserves your list filters and page.

R&D is currently standalone. It does not record operational sample or reagent consumption, run Lab protocols, or automatically connect notebook content to Lab records. Saved notebooks and attachments have no permanent-delete action or automatic expiry.

## Read sizes and recorded times

File summaries use KiB, MiB, GiB and larger binary units, each 1,024 times the
previous unit. Recorded timestamps identify their display timezone. A recorded
calendar date stays on its original day; it is not converted into a timestamp.
Zero is a recorded value; **Not recorded** means no value was supplied.
