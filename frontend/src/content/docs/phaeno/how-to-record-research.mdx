# How to record an R&D experiment

Illustrations refreshed and reviewed October 24, 2026, from current components
with fictional records.

Use this walkthrough to organize exploratory work, capture dated notes and measurements, and retain the history of an experiment. R&D is a shared electronic notebook. You can adapt its sections as the work develops.

## Before you start

Select the Phaeno organization and open **R&D** in the POMS toolbar. On a narrow screen, open it from the user menu. You need an active Phaeno membership with the **R&D researcher** role, or platform administrator access. Ask a platform administrator to assign the role through **User management** if needed.

All authorized researchers can read and edit the team's notebooks. There are no private projects. Department selection does not restrict access. Record information suitable for that shared audience, without credentials or confidential Customer records.

These screenshots show actual application components with fictional demonstration records. Numbered markers match the explanations below each image. The example values illustrate recording a notebook; they are not a validated experimental method or scientific evidence. No hosted records were created to make the illustrations.

## 1. Find or create a project

Open **Projects** and search before creating another project. A project groups related experiments.

![R&D Projects showing the Projects and Experiments sidebar, Create project, search and fictional project links.](/docs/phaeno/screenshots/research-20261017/01-projects.jpg "Projects groups related work; Experiments searches across the notebook.")

1. **Projects:** browse the team's project groups.
2. **Experiments:** find experiments across projects, including completed work.
3. **Create project:** open the project form.
4. **Project name:** open the project's dedicated workspace. The list also shows its description and experiment count.

Choose **Create project** when the work needs a new group.

![Create project dialog with a fictional project name, optional description and Create project action.](/docs/phaeno/screenshots/research-20261017/02-create-project.jpg "Give the project a recognizable purpose.")

1. **Project name:** enter a name that colleagues can find again.
2. **Description:** optionally explain the research question or scope.
3. **Create project:** save the project, then open its name to add an experiment. Cancel closes the form without creating one; discard any unsaved changes when prompted.

## 2. Create an experiment

From the project, choose **Create experiment**. You can also create one from **Experiments** and select its project there.

![Create experiment dialog showing the title, selected project, optional experiment date and Create experiment button.](/docs/phaeno/screenshots/research-20261017/03-create-experiment.jpg "Confirm the project and the date before creating the notebook.")

1. **Experiment title:** describe the specific investigation or run.
2. **Project:** confirm where the experiment belongs.
3. **Experiment date:** optionally record the date of the work. The first entry uses this date; when it is blank, the first entry uses today's date in your browser's local time.
4. **Create experiment:** save the experiment and its first notebook entry.

## 3. Open the notebook entry

An experiment opens as an overview of dated entry summaries. A new experiment starts with one entry; the screenshot shows the same entry after it has been renamed and saved.

![Active demonstration experiment with project and date context, the notebook entry title, Add entry and experiment Actions.](/docs/phaeno/screenshots/research-20261017/04-experiment.jpg "Open an entry by its title to read its saved content.")

1. **Experiment context:** check the project, Active or Completed status, and experiment date.
2. **Entry title:** open the saved notebook. The card identifies the entry date and who recorded and last saved it.
3. **Add entry:** create another dated entry when the work continues.
4. **Actions:** manage the experiment, including completion, copying setup and history.

The entry first opens for reading. Choose **Actions → Edit entry** to change it.

![Saved notebook entry with its Actions menu open, showing Edit entry and View history.](/docs/phaeno/screenshots/research-20261017/06-entry-actions.jpg "Editing is an explicit action from the saved entry.")

1. **Edit entry:** open the editor while the experiment is Active.
2. **View history:** inspect previous saved revisions without changing the entry.
3. **Back to experiment:** return to the overview and its entry page.

## 4. Adapt the sections to the work

The initial entry offers Purpose, Method, Observations, Results and Conclusions. Use as many or as few as the experiment needs.

![Entry editor showing the entry title and date, editable Purpose label, Scientific section selection, Notes and a section Actions menu.](/docs/phaeno/screenshots/research-20261017/07-entry-editor.jpg "Section labels are flexible; Scientific section records their meaning.")

1. **Title and entry date:** identify this particular session of work. The entry date describes the experiment; it does not change the recorded save times.
2. **Section label:** rename a section in language appropriate to the experiment.
3. **Scientific section:** choose its meaning independently of its label. Purpose and Method text are retained by Copy setup; other text is cleared.
4. **Notes:** record multiline text, scientific characters, conditions, deviations and observations.
5. **Section Actions:** move a section up or down, or remove it from the draft. Add more text sections or tables at the bottom of the editor.

Sections are optional, but every section you keep needs a label. Required fields have an asterisk, and validation identifies what to correct. Changes stay in the editor until you save.

## 5. Add measurements and supporting files

Choose **Add table** for structured observations. Give it a meaningful label and Scientific section, then edit its headings and cells.

![Results table editor with column headings and units, two fictional measurement rows, table Actions, Add section controls, file upload and Save changes.](/docs/phaeno/screenshots/research-20261017/08-table-and-save.jpg "Record units and context; notebook tables retain values without calculating or validating them.")

1. **Column headings:** name each measurement and include units where appropriate.
2. **Table cells:** enter the observed values. The notebook does not calculate, convert units or judge scientific validity.
3. **Table Actions:** add rows or columns. Individual removal controls appear beside existing rows and columns. A table supports up to 1,000 rows and 30 columns.
4. **Add text section / Add table:** extend the entry when the experiment needs more structure.
5. **Attach a file:** choose a supporting file, up to 100 MiB each. Wait for upload, verification and scanning. Then save the entry to record the attachment in its notebook. If an upload fails, your notes remain available to save independently.
6. **Save changes:** persist the entry and its revision history. There is no automatic save. Cancel discards your draft only after confirmation when changes are present.

A save or upload in progress must finish before leaving. If file storage or scanning is temporarily unavailable, retry the upload when service is restored. Uploaded files are retained even when not subsequently attached to an entry.

## 6. Check the saved entry

After saving, read the entry to confirm that the intended notes, values and files were recorded.

![Saved demonstration notebook with recorded and last-saved attribution, scientific sections and the two-row results table.](/docs/phaeno/screenshots/research-20261017/09-saved-entry.jpg "Review the saved content before moving on.")

1. **Attribution:** Recorded by and Last saved by identify the people and application save times separately from the entry date.
2. **Sections:** review the saved narrative and any deviations or conclusions.
3. **Table:** verify the headings, units and entered values.

Use an attachment's action to download it. Supported verified images also offer a preview. Other formats download for their original applications. Removing a file section from a later draft does not delete its original bytes; older saved revisions retain the attachment.

## 7. Add the next dated entry

Return to the experiment and choose **Add entry** when you need another dated record in the same experiment.

![Add notebook entry dialog explaining permanent entry creation, with title, date, Cancel and Create entry.](/docs/phaeno/screenshots/research-20261017/05-add-entry.jpg "Create entry records a new entry before opening its editor.")

1. **Creation explanation:** read what will be recorded before confirming.
2. **Entry title:** describe the session or stage of work.
3. **Entry date:** review the date; it initially uses today's date in your browser's local time.
4. **Create entry:** permanently record the entry and open its editor. Canceling this dialog creates nothing. Canceling the editor afterward keeps the entry that you already confirmed.

Each experiment lists 25 entry summaries per page. Use **Previous** and **Next** to reach older entries, then open the relevant title.

## 8. Review history and reconcile shared edits

Choose **View history** from the entry's Actions menu, then select a revision. Projects and experiments also have their own history.

![Entry history dialog showing a saved revision, its selected snapshot's dated content and Close history.](/docs/phaeno/screenshots/research-20261017/10-history.jpg "History shows saved content, author and time; it is read-only.")

1. **Revision list:** select a save by its revision number, action, author and time. Use the history page controls when needed.
2. **Saved snapshot:** read that revision's title, date, sections, tables and retained attachments. History does not restore a previous revision automatically.
3. **Close history:** return to the current record.

If another researcher saves first, your input stays in the editor. Review the latest saved entry. Its **Actions** let you keep your edits against that revision or use the latest saved entry. Keeping your edits requires another explicit save and can replace the other researcher's values, so reconcile the work before saving. **Refresh latest saved entry** reloads the saved version while retaining your draft.

If the experiment is completed during editing, use **Reopen experiment** inside the editor and confirm. Your draft stays in place. Review the latest entry and choose **I reviewed the latest entry; keep my edits** before saving. The same review becomes available when a colleague reopens the experiment elsewhere.

## 9. Complete or reopen the experiment

When recording is finished, choose **Actions → Complete experiment** from the experiment overview.

![Complete experiment confirmation with a body explaining the read-only notebook and retained evidence, plus Cancel and Complete experiment.](/docs/phaeno/screenshots/research-20261017/11-complete.jpg "Completion makes the notebook read-only until it is reopened.")

1. **Consequence:** check the named experiment and read the effect on editing.
2. **Cancel:** keep the experiment Active.
3. **Complete experiment:** confirm completion. Saved evidence and history remain available.

Completion requires no approval or filled scientific sections. It is a recording status, not a scientific sign-off or Customer release.

![Completed experiment with Actions showing Reopen experiment, Copy setup and View history.](/docs/phaeno/screenshots/research-20261017/12-reopen-and-copy.jpg "Completed notebooks remain readable and can be reopened.")

1. **Completed status:** the notebook can be read, but entries cannot be added or edited.
2. **Reopen experiment:** confirm to let the research team edit again. The action retains its actor and time.
3. **Copy setup:** start another experiment from this notebook's structure.

## 10. Repeat the setup without carrying forward results

Choose **Copy setup** from the experiment's Actions menu. This works from Active and Completed experiments.

![Copy experiment setup dialog showing a new title, destination project, optional date, clearing explanation and Copy setup.](/docs/phaeno/screenshots/research-20261017/13-copy-setup.jpg "A copy starts a new Active experiment with a fresh history.")

1. **New title:** identify the next experiment. Review and rename copied entry titles as needed.
2. **Project:** select the destination project.
3. **Experiment date:** optionally set the next experiment's date. Its initial entries use this date, otherwise today's browser-local date.
4. **Copy setup:** retain section labels and order, Purpose and Method text, and table headings with no rows. Clear observations, results, conclusions, custom text, files and previous history. Review the copied method before starting the next experiment.

## 11. Find earlier work

Open **Experiments** to search across the team's work.

![Experiment discovery showing a buffer search, status and project filters, an Active result and result pagination.](/docs/phaeno/screenshots/research-20261017/14-find-experiments.jpg "Search saved notebook text and tables, then open an experiment's title.")

1. **Search:** match experiment titles and saved notebook text or table content. Attachment contents are not searched.
2. **Status and project:** narrow the results to the relevant group or Active/Completed work. **Clear all** removes the filters.
3. **Experiment title:** open its overview, then the relevant entry. Returning to the list preserves your filters and page.
4. **Result count and pages:** check the full matching count and use Previous/Next when there is more than one page.

R&D is currently standalone. It does not run approved Lab protocols, record operational sample or reagent consumption, or automatically link notebook content to Lab records. Use the appropriate Lab workflow for those operations. Saved notebooks and attachments have no permanent-delete action or automatic expiry.

See [R&D notebooks](/docs/phaeno/research-notebooks) for the reference guide and [POMS user administration](/docs/phaeno/organization-and-user-administration) for role administration.
