# Customer onboarding illustrations — October 15, 2026

Fifteen screenshots render actual Portal application components with explicitly
fictional Company, person, Department, request, entitlement and billing records.
They illustrate the supported controls and states; they do not prove live
identity, email delivery, access acceptance, billing or request processing.

The capture preview uses read-only in-memory responses. No operational write,
invitation or email is sent, and no real Customer record, credential, invitation
token, personal contact or confidential detail is captured. Invitation acceptance
is the actual review component after a fictional sign-in. Finance choices and
addresses are demonstration values, not approved commercial/tax facts.

The original captured JPEG bytes remain unchanged. The shared documentation image
renderer adds 73 numbered markers from `onboarding-screenshots.ts`; matching
written explanations live in `how-to-onboard-customer.mdx`. Captions identify the
illustrations. Keep images, metadata and explanations together on recapture.

The Department form shows the upper fields and fixed footer. Billing setup shows
the editable fields; Finance approval shows the lower, saved-profile section.
Other tall pages use full-page captures. No composite or reconstructed screen is
presented as actual application UI.
